# K4All bootc

This directory contains the **bootc-based** K4All distribution. It replaces the previous Fedora CoreOS + Butane/Ignition approach with a more streamlined bootc image that can be installed via Anaconda.

## Overview

- **Base image**: `quay.io/centos-bootc/centos-bootc:stream9`
- **Pre-installed**: kubeadm, kubelet, kubectl, CRI-O, OVS, Helm, and all K4All scripts
- **Installer**: Anaconda with K4All addon for configuration
- **Updates**: `bootc upgrade` (image-based updates)

## Directory Structure

```
bootc/
├── Containerfile           # Main bootc image definition
├── overlay/                # Files copied into the image
│   ├── etc/
│   │   ├── yum.repos.d/    # Kubernetes repo
│   │   ├── sysctl.d/       # Kernel parameters
│   │   └── k4all-config.json.default
│   └── usr/local/
│       ├── bin/            # K4All scripts + overrides
│       └── share/          # Manifests, values, yamls
├── systemd/                # Systemd units for K4All services
├── iso/                    # ISO remaster files
│   ├── images/             # k4all_updates.img (Anaconda addon)
│   └── ks/                 # Kickstart templates
├── scripts/                # Build scripts
│   ├── build-image.sh      # Build OCI image
│   ├── build-iso.sh        # Build ISO via bootc-image-builder
│   └── remaster-iso.sh     # Add K4All addon to ISO
└── README.md
```

## Build Process

### 1. Build the bootc OCI image

```bash
cd bootc
./scripts/build-image.sh

# Or with custom name/tag:
IMAGE_NAME=my-registry/k4all-bootc IMAGE_TAG=v2.0.0 ./scripts/build-image.sh
```

### 2. Push the image (optional, for remote installs)

```bash
podman push ghcr.io/gpillon/k4all-bootc:latest
```

### 3. Build the ISO

```bash
./scripts/build-iso.sh ghcr.io/gpillon/k4all-bootc:latest
```

### 4. Build the Anaconda addon

```bash
cd ../k4all-anaconda-addon
make
cp k4all_addon_updates.img ../bootc/iso/images/k4all_updates.img
```

### 5. Remaster the ISO with the addon

```bash
./scripts/remaster-iso.sh output/bootiso-*.iso
```

## Installation

1. Boot from the ISO
2. Anaconda will launch with the K4All addon
3. Configure:
   - **Standard Anaconda**: disk, network, timezone, root password
   - **K4All addon**: node role (bootstrap/control/worker), HA, CNI, features
4. Install
5. First boot: K4All systemd services configure Kubernetes automatically

## Kickstart (Unattended Install)

Create a kickstart file with the K4All addon section:

```kickstart
# Standard kickstart directives
lang en_US.UTF-8
keyboard us
timezone UTC
rootpw --plaintext changeme
bootloader --location=mbr
clearpart --all --initlabel
autopart

# K4All addon configuration
%addon com_k4all_installer --role=bootstrap --cni=calico
{
  "cluster": {
    "ha": { "type": "none" }
  },
  "features": {
    "virt": { "enabled": "false" }
  }
}
%end

# Install
reboot
```

## Node Roles

- **bootstrap**: First node, runs `kubeadm init`, creates cluster
- **control**: Additional control plane nodes, joins as control plane
- **worker**: Worker nodes, joins as worker

The node role is stored in `/etc/node-type` and the K4All role dispatcher copies the appropriate scripts at first boot.

## Updates

To update a running K4All node:

```bash
# Check current image
bootc status

# Upgrade to latest
bootc upgrade

# Or switch to specific version
bootc switch ghcr.io/gpillon/k4all-bootc:v2.1.0

# Reboot to apply
systemctl reboot
```

## Configuration

The main configuration file is `/etc/k4all-config.json`. It can be:
- Generated by Anaconda addon during install
- Provided via kickstart
- Manually created before first boot

See `overlay/etc/k4all-config.json.default` for the full schema.
